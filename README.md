# 방과후 스마트 정산 시스템

초등 방과후학교의 초3 지원금·자유수강권 지원금 정산을 계산·관리하는 웹 애플리케이션입니다. 별도 빌드 과정 없이 브라우저에서 바로 실행되는 정적(static) HTML/JS 페이지입니다.

## 실행 방법

빌드나 `npm install` 과정이 필요 없습니다. [index.html](index.html)을 브라우저로 열면 바로 실행됩니다.

- 더블클릭으로 직접 열거나
- 로컬 정적 서버(예: `npx serve .`, VS Code Live Server 등)로 열어도 됩니다.

데이터는 브라우저의 로컬 저장소(IndexedDB)에 저장되며, 상단의 "백업"/"복구" 버튼으로 JSON 파일로 내보내고 불러올 수 있습니다.

## 외부 라이브러리

Bootstrap, xlsx(SheetJS), html2canvas, JSZip, ExcelJS, FileSaver는 CDN이 아니라 [vendor/](vendor) 아래 로컬 사본을 사용합니다. 학교 네트워크의 CDN 차단이나 CDN 장애로 엑셀 생성 등 핵심 기능이 멈추는 것을 막기 위함입니다. 버전을 올리려면 해당 CDN에서 새 버전을 받아 `vendor/`의 같은 경로에 덮어쓰고 [index.html](index.html)의 스크립트/링크 태그 버전 주석을 갱신하세요.

## 업데이트 알림 모달

새 기능을 배포할 때는 [updates.js](updates.js)의 `window.APP_UPDATES` 배열에 항목을 하나 추가하면 됩니다(구글시트 연동 아님). `<script>` 태그로 불러오는 이유는, `fetch()`로 JSON을 읽으면 `index.html`을 더블클릭으로 직접 열었을 때(파일 프로토콜) 브라우저가 로컬 파일 fetch를 막아버리기 때문입니다.

```js
{ date: '2026-07-10', message: '사용자에게 보여줄 문구', until: '2026-07-24' }
```

- `date`: 공지가 노출되기 시작하는 날짜
- `until`: 생략하면 `date`로부터 14일 후 자동으로 사라집니다. 특정 날짜까지만 보여주고 싶으면 명시하세요.
- 오래된 항목은 배열에 남겨둬도 자동으로 안 보이므로 굳이 지우지 않아도 됩니다(이력 겸용).

이 공지는 **시작 모달**에서 "이번 업데이트 내용"으로 보여집니다. 같은 창에 **"내 장부에 미친 영향"** 칸이 함께 있어서, 이번 업데이트로 금액이 달라진 학생이 있으면 이전/변경/차이 표와 엑셀 내려받기가 나오고, 없으면 "변경 사항 없습니다"로 끝납니다([core-rules.md](core-rules.md) 제7조).

- **자동으로 뜨는 때:** 마지막으로 본 버전 ≠ 현재 버전, 즉 업데이트 후 첫 접속 1회. 같은 버전에서 다시 열면 뜨지 않습니다.
- **수동:** 헤더의 `[업데이트]` 버튼으로 언제든 열 수 있습니다.
- **금액이 달라졌을 때만** X 버튼이 숨겨지고 ESC·바깥 클릭이 막혀, `[확인했습니다]`로만 넘어갈 수 있습니다.

> ⚠ 이 모달을 "접속할 때마다" 띄우도록 바꾸지 마세요. 공지는 기본 14일간 노출되어 평상시에도 활성 공지가 늘 여러 건 쌓여 있고, 그러면 창이 거의 매일 뜨는데 금액 영향 칸은 대개 "변경 사항 없습니다"가 됩니다. 2주면 사용자가 `[확인]`을 반사적으로 누르는 습관이 생기고, 정작 금액이 달라졌을 때도 그냥 넘기게 됩니다.

2026-09-17 이전에는 화면 최상단에 흐르는 띠 배너(티커)로 공지를 보여줬습니다. 업데이트 소식과 "그래서 내 금액이 어떻게 됐나"가 서로 다른 곳에 흩어져 있어 정작 중요한 금액 변동을 놓치기 쉬워서, 한 창으로 통합하고 티커는 제거했습니다.

## 테스트

정산 계산 엔진([app-engine.js](app-engine.js))에 대한 테스트가 [test/](test)에 있습니다. Node.js 내장 테스트 러너를 사용하며 별도 설치가 필요 없습니다.

### 1) 회귀 테스트 — `npm test`

```
npm test
```

"이 입력에는 이 금액이 나와야 한다"를 손으로 못박아 둔 테스트입니다. 핵심 회계 규칙([core-rules.md](core-rules.md)의 헌법 1~3조: 예산 한도, 항목/강좌 우선 차감, 개별 강좌 규칙의 독립성)이 깨지지 않았는지 이 테스트로 먼저 확인한 뒤 엔진 로직을 수정하세요. push/PR 때마다 GitHub Actions가 자동으로 돌립니다.

### 2) 퍼즈 테스트 — `npm run fuzz`

```
npm run fuzz                          # 기본 2,000건
npm run fuzz -- 5000                  # 5,000건
node test/fuzz-engine.js --seed 116   # 특정 시나리오 하나만 상세 덤프
```

회귀 테스트는 **사람이 미리 생각해낸 경우**만 검사할 수 있습니다. [test/fuzz-engine.js](test/fuzz-engine.js)는 반대 방향입니다. 학생·강좌·환불·조정·마감·자유수강권 지원시점을 무작위로 조합한 시나리오를 수천 건 만들어 실제 엔진으로 돌린 뒤, 금액이 얼마인지는 따지지 않고 **어떤 경우에도 반드시 참이어야 하는 성질(불변식)**만 검사합니다.

| 불변식 | 내용 |
| --- | --- |
| A1 | 초3 + 자유 + 자부담 = 청구액 (1원도 안 틀리게) |
| A2 | 어떤 금액도 음수가 될 수 없음 |
| A3 | 비대상자에게 지원금이 배정되지 않음 |
| A4 | 차수별 합계 = 분기 합계 (헌법 제2조) |
| A5 | 차수 내부에서도 3분할이 맞음 |
| A6 | 한도를 넘겼는데 경고 없이 조용히 넘어가지 않음 (+ 거짓 경보도 없음) |
| A7 | 멱등성 — 데이터를 안 바꾸고 재연산만 하면 결과가 같음 |
| A9 | 경로 동등성 — 조정을 환불보다 늦게 해도 최종 금액이 같음 (헌법 제6조) |

시나리오는 seed 기반 결정론적 난수로 만들기 때문에, 위반이 보고된 seed를 `--seed`로 다시 돌리면 언제나 똑같이 재현됩니다.

2026-09-17에 이 퍼즈로 실제 금액이 틀어지는 결함 5건을 찾아 고쳤고, 이어서 조정(adjust)과 환불(refund)의 회계 성격이 다르다는 점([core-rules.md](core-rules.md) 제6조)을 엔진에 반영했습니다. 재발 방지 테스트는 [test/regression-2026-09-17.test.js](test/regression-2026-09-17.test.js)에 있습니다. 엔진을 크게 손댄 뒤에는 `npm test`뿐 아니라 `npm run fuzz -- 5000` 정도를 함께 돌려보는 것을 권합니다.
